# Evidence index

This directory holds the sanitized artifacts that back the PROVEN rows in [`../CLAIMS.md`](../CLAIMS.md). Each artifact is written by a command from a real run and is never edited by hand. JSON artifacts carry a `capturedAt` timestamp and pass through the same sanitizer as Selo's report evidence, so payment signatures, authorization headers, cookies and anything named like a secret are replaced by their SHA-256 before they are written.

Commands are run from the repository root. `--out docs/evidence` is resolved against the directory the command was started from.

## Commands

### `verify:g1` (read-only, never pays)

```
pnpm --filter @selo/api verify:g1 -- --domain <public host> --pay-to <payTo address> --preflight <preflight id> [--out docs/evidence]
```

Sends one unpaid `POST https://<domain>/v1/release-test` with a valid body for the given preflight and decodes the 402 challenge. It then pages through the facilitator's Bazaar resources and merchants and reads the Mainnet merchant leaderboard for each source. It prints one `PASS` or `FAIL` line per check (A01 402, A02 network/asset/payTo, A03 challenge tag, A04 discovery metadata, A07 Bazaar listing, merchant record, A08 challenge leaderboard row) and exits `0` only when every check passes. Volume that appears only under `direct` or `dev` is reported as a FAIL. Network errors and unexpected response shapes are reported as FAIL with the reason. It never signs anything.

### `pay:selo` (customer-side, one payment at most)

```
pnpm --filter @selo/api pay:selo -- --api <https base url> --preflight <preflight id> [--pay-to <expected payTo>] [--expected-status 200] [--idempotency-key <key>] [--out docs/evidence] [--mainnet-i-have-approval]
```

Reads the payer's recovery words from `SELO_CLIENT_MNEMONIC` in the environment (never from the command line) and never prints them. It sends one unpaid request, prints the price, network, payTo and tag from the 402 and then refuses unless:

- the network is Algorand Testnet, or it is Algorand Mainnet and `--mainnet-i-have-approval` was passed by the wallet owner;
- the payer is neither the payTo address nor Selo's own operating wallet (no self-payment);
- when `--pay-to` is given, the 402's payTo is exactly that address (on Mainnet `--pay-to` is required together with `--mainnet-i-have-approval`);
- the 402 offers exactly one Algorand USDC requirement priced above zero and at most 5.00 USDC.

When allowed, it signs exactly that one requirement, sends the paid request once with an `Idempotency-Key` header and prints Selo's response and the settlement transaction ID. The key is derived from the preflight id and the payer address unless `--idempotency-key` is given, and is printed before paying; rerunning with the same key (for example after a proxy timeout) returns the existing job and never settles a second payment. With `--out`, the evidence file replaces the report link with the SHA-256 of its token. It never retries a payment, never loops and never follows a redirect: a 3xx on either request stops the run with nothing further sent. If the paid request fails in transit or is redirected, it stops and says the payment may have settled. An error before the paid request is reported as "nothing was sent".

### Testnet accounts

```
pnpm --filter @selo/api account:new -- --role client|operator
pnpm --filter @selo/api account:optin -- --role client|operator [--mainnet-i-have-approval]
pnpm --filter @selo/api account:status
```

`account:new` generates an account and appends `SELO_CLIENT_MNEMONIC` or `SELO_OPERATOR_MNEMONIC` to `apps/api/.env` only if that key is absent (it never overwrites), with file mode 0600, and prints only the address and funding steps: ALGO from https://bank.testnet.algorand.network/, then the USDC opt-in, then Testnet USDC from https://faucet.circle.com/. `account:optin` submits a 0-amount USDC opt-in (ASA 10458941 on Testnet) for that account on the configured network, refusing Mainnet without `--mainnet-i-have-approval`. `account:status` is read-only and prints the ALGO and USDC balances and opt-in state of both accounts.
