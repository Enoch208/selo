# Test report: the release gate

Every scenario below is an automated test that runs in CI against a real PostgreSQL database.
Fakes stand only at the facilitator, the signer and the chain, and exist only in tests. Run one
test by name with `pnpm test -t "<name>"`. The full verbose output of the last recorded run is in
[`evidence/g3-test-suite.txt`](evidence/g3-test-suite.txt).

## Required scenarios

| Scenario                                              | Expected                                                | Tests                                                                                                                                                                                                                                                                                                                          |
| ----------------------------------------------------- | ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Health 200, paid JSON violates the contract           | Genuine FAIL with evidence; CI blocks                   | "broken-v1 is healthy and settles, yet the paid response fails the release contract"; "blocks broken-v1 with exit 1 and allows fixed-v2 with exit 0 at the same URL"; "A18: a response violating the expected schema produces FAIL"                                                                                            |
| Corrected response, every check proven                | Genuine PASS; CI allows promotion                       | "fixed-v2 passes all five checks with evidence"; "FAIL, fix, PASS: the same URL fails on broken-v1 and passes once fixed-v2 ships"; "exits 0 and allows promotion only on a fully evidenced PASS"                                                                                                                              |
| Inbound payment not confirmed                         | No downstream payment or execution                      | "A12: inbound settles before the first downstream request"; "refuses a job whose inbound payment has not settled and contacts no target"; "a retry of an unresolved request is answered from the held job without settling again"                                                                                              |
| Duplicate request with the same idempotency key       | No extra inbound settlement                             | "A21: the same Idempotency-Key with two different payments settles once"; "A21: the duplicate paid request returns the same report and pays the target once"; "recovers an interrupted paid call by resuming, settling only once"                                                                                              |
| Downstream transaction ambiguous after send           | Held unresolved; no repeat spend                        | "A17: a timeout with ambiguous payment state stops further spending"; "an outstanding unresolved payment blocks before scenario and job budgets"; "holds an unresolved settlement and never pays again without --resume"                                                                                                       |
| Concurrent spend reservations                         | Total never exceeds the job cap                         | "A16: three parallel 0.05 reservations against a 0.10 job reserve exactly two"; "A16: thirty parallel mixed-size reservations against 0.50 never overspend"; "I2: the budget invariant rejects settled + reserved + unresolved above max spend"                                                                                |
| Authorization expired or route changed                | Reject or INCONCLUSIVE; never pay an unauthorized route | "authorization missing, unverified, then expired"; "does not replay when the authorization lapsed after the paid call"; "expired authorization wins over every later failure"                                                                                                                                                  |
| Private IP, redirect, DNS rebinding                   | Blocked by the safe fetch                               | "A10: a private-network target is rejected before any request"; "blocks when any resolved record is private even if another is public"; "blocks a redirect whose hop now resolves to a private address"; "blocks the fourth redirect"                                                                                          |
| Missing evidence, missing report, invalid attestation | CI blocks; never PASS                                   | "exits 2 when a PASS lacks a check, evidence or a payment leg"; "exits 2 when the answer is not a report at all"; "exits 2 when a report claims PASS that its own checks do not support"; "refuses an attestation whose signed fields were changed"; "refuses a PASS for another release, another target or no release at all" |
| Secrets in payloads or logs                           | Redacted from reports, artifacts and terminal           | "A22: logs, evidence, reports and the evidence packet contain no wallet secret"; "never prints or stores the mnemonic, the signed payment or the report token"                                                                                                                                                                 |

The Mainnet counterpart of the first two rows is in [`evidence/`](evidence/README.md), with
transaction ids anyone can check on an Algorand explorer.
